# CROSS-SUPERSET BOUNDARY RULES

## Objective

Consolidate all cross-superset integrity rules established during REPAC vNext Element-Layer Stabilization.

This document serves as the **authoritative boundary control layer** governing:

* Element classification
* Cross-superset interpretation
* Prevention of semantic drift
* OWL/TTL modelling alignment

---

## Scope

This document governs the boundaries between the following supersets:

* Work
* Governance
* Communication
* Collaboration
* Value

---

## Foundational Principle

Each REPAC superset represents a **distinct analytical dimension**.

No superset may absorb, redefine, or collapse into another.

---

# Core Superset Definitions (Locked)

### Work

Represents **execution**:

* Tasks
* Activities
* Operations
* Actions that produce change

---

### Governance

Represents **structured authority, decision-rights, control, and accountability**:

* Authority structures
* Decision allocation
* Control mechanisms
* Oversight and accountability

---

### Communication

Represents **information exchange**:

* Messages
* Signals
* Transmission of meaning
* Expression of intent or status

---

### Collaboration

Represents **interaction between actors**:

* Participation
* Joint engagement
* Interaction structures
* Cooperative dynamics

---

### Value

Represents **worth or significance**:

* Benefit
* Cost
* Utility
* Impact

---

# Universal Boundary Rules (Apply Globally)

## UB-01 — Non-Equivalence

No superset is equivalent to another.

* Work is not Governance
* Work is not Communication
* Work is not Collaboration
* Work is not Value
* Governance is not Communication
* Governance is not Value
* Communication is not Collaboration
* Communication is not Value

---

## UB-02 — Co-Occurrence Rule

Supersets may co-occur in reality but must not be modeled as the same construct.

---

## UB-03 — Non-Containment

No superset contains another as a subtype.

---

## UB-04 — Interpretation Discipline

Classification is determined by **what is being modeled**, not by context or proximity.

---

## UB-05 — No Role Leakage

Actors, roles, or participation do not redefine the superset classification of an element.

---

# Work Boundary Rules

## W-01 — Execution Rule

Work models execution only.

---

## W-02 — Governance Separation

Approval, control, and accountability structures belong to Governance, not Work.

---

## W-03 — Communication Separation

Messages, instructions, and signals belong to Communication, not Work.

---

## W-04 — Collaboration Separation

Interaction between actors belongs to Collaboration, not Work.

---

## W-05 — Value Separation

Outcomes may carry value, but Work itself is not Value.

---

# Governance Boundary Rules

## G-01 — Authority Rule

Governance models authority, decision-rights, control, and accountability.

---

## G-02 — Execution Separation

Governance is not execution.

---

## G-03 — Communication Separation

Governance may be expressed through Communication but is not Communication.

---

## G-04 — Value Separation

Governance may act on Value but is not Value.

---

## G-05 — Informal Governance Rule

Informal authority, control, or accountability structures remain Governance.

---

## C-05 — Value Separation

# Classification Heuristic (Operational Use)

When classifying any construct, apply:

1. Is this **execution**? → Work
2. Is this **authority/control/accountability**? → Governance
3. Is this **information exchange**? → Communication
4. Is this **interaction between actors**? → Collaboration
5. Is this **worth or evaluation**? → Value

If multiple apply:

* Model each aspect separately
* Do not collapse into a single superset
