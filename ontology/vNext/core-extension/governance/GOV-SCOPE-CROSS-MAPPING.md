# Governance ↔ Scope Cross-Superset Mapping
VNEXT Phase G2 — Boundary Stress Mapping

## Purpose

This artifact stress-tests the analytical boundary between the Governance Superset (Layer 1) and the Scope Superset (frozen pilot constructs).

Governance defines structural power, entitlement, enforcement, and oversight constructs within a defined Scope.

Scope defines the analytical boundary conditions of what is included, excluded, or constrained in the system under examination.

This mapping prevents:
- Governance absorbing boundary definition
- Scope absorbing authority allocation
- Semantic drift during later formalization

---

# Mapping Framework

For each Governance Layer 1 element:
- Touches Scope when…
- Is not Scope because…
- Collapse Indicator (if true, analysis belongs in Scope)

---

# GOV-EL-01 — Authority Structure

## Touches Scope When
Authority structures are defined differently across distinct system boundaries.

## Is Not Scope Because
Authority Structure concerns distribution of power within a defined boundary, not the definition of that boundary itself.

## Collapse Indicator
If analysis requires redefining what is inside or outside the system, the issue belongs to Scope, not Governance.

---

# GOV-EL-02 — Decision Rights Allocation

## Touches Scope When
Decision rights vary depending on what domain, function, or boundary is considered.

## Is Not Scope Because
Decision Rights Allocation assigns entitlement within a boundary; it does not determine which domains are included in analysis.

## Collapse Indicator
If entitlement ambiguity stems from unclear system inclusion/exclusion, the defect is in Scope.

---

# GOV-EL-03 — Legitimacy Basis

## Touches Scope When
Legitimacy claims reference mandates that derive from external boundary conditions (e.g., regulatory scope).

## Is Not Scope Because
Legitimacy concerns acceptance of authority, not system definition.

## Collapse Indicator
If actors dispute what system is being governed, the issue belongs to Scope clarification.

---

# GOV-EL-04 — Enforcement Mechanism

## Touches Scope When
Enforcement jurisdiction is limited by boundary definitions.

## Is Not Scope Because
Enforcement concerns consequence structures, not jurisdictional inclusion.

## Collapse Indicator
If enforcement cannot operate because system limits are undefined, Scope is under-specified.

---

# GOV-EL-05 — Escalation Logic

## Touches Scope When
Escalation pathways cross defined organizational or functional boundaries.

## Is Not Scope Because
Escalation Logic defines structured elevation within or across boundaries; it does not define those boundaries.

## Collapse Indicator
If escalation confusion arises because boundary authority is unclear, Scope modelling must be revisited.

---

# GOV-EL-06 — Oversight Construct

## Touches Scope When
Oversight responsibility is tied to defined analytical or jurisdictional boundaries.

## Is Not Scope Because
Oversight evaluates governance performance; it does not determine inclusion criteria.

## Collapse Indicator
If oversight lacks clarity about what it is responsible for evaluating, Scope boundaries are ambiguous.

---

# GOV-EL-07 — Compliance Mechanism

## Touches Scope When
Compliance tracking is limited to defined regulatory or operational domains.

## Is Not Scope Because
Compliance Mechanism concerns measurement and traceability, not domain inclusion.

## Collapse Indicator
If compliance metrics cannot be defined because system boundaries are undefined, the issue is Scope-related.

---

# GOV-EL-08 — Informal Governance Overlay

## Touches Scope When
Informal authority operates differently across boundary segments.

## Is Not Scope Because
Informal Governance Overlay concerns patterned influence structures, not structural inclusion or exclusion.

## Collapse Indicator
If informal systems exist because formal boundaries are misdrawn, Scope must be examined.

---

# Cross-Case Validation Check

The five Governance mini-cases were re-examined for boundary collapse.

Observation:
- In cases of shadow process and cross-team dependency breakdown, partial Scope ambiguity amplified Governance weaknesses.
- However, Governance constructs remained analytically distinct once system boundaries were clarified.

No Governance Layer 1 element required reclassification into Scope.

---

# Boundary Integrity Conclusion

Governance Layer 1 remains structurally distinct from Scope.

Governance:
- Distributes power
- Assigns entitlement
- Enforces consequence
- Structures escalation
- Monitors governance performance

Scope:
- Defines inclusion/exclusion boundaries
- Establishes system limits
- Constrains analytical domain

No collapse detected under current modelling.
