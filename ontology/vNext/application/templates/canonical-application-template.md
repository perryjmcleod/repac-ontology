# REPAC vNext — Canonical Application Template

## 0. Metadata
- Case ID:
- Case Title:
- Date:
- Version:
- Status: (Draft | Frozen | Deprecated)
- Primary Superset:
- Secondary Supersets:
- Analytical Function: (Demonstration | Contrast | Stress Test | Boundary Proof)
- Source Type: (Internal | External | Mixed)
- Confidentiality: (Public | Redacted | Private)

## 1. Problem Statement
State the outcome or situation being analysed in one to three sentences.
Rules:
- No causes stated.
- No recommendations.
- No “should” language.
- No domain assignments beyond what is declared in Metadata.

## 2. Observed Outcome and Salient Facts
List only observations necessary to constrain analysis.
Rules:
- Observations only; do not interpret.
- Do not attribute intent.
- Do not introduce causal language.

## 3. Scope and Assumptions for this Analysis
Declare the boundary commitments of this application.
Include:
- Included scope
- Excluded scope
- Fixed assumptions
- Deferred questions
Rules:
- Assumptions must be explicit.
- No backfilling with conclusions.

## 4. Candidate Explanatory Hypotheses (Pre-REPAC)
Capture the common single-factor explanations that would typically be offered.
Rules:
- This section records competing narratives without endorsing them.
- Do not rebut here.

## 5. REPAC Domain Pass (Superset-Level)
For each relevant Superset, state:
- Why it is materially implicated in this case (one to two sentences)
- What would count as evidence in this domain (bullets)
Rules:
- No elements instantiated here.
- No set-level decomposition here.
- Do not make claims about what is true.

## 6. REPAC Set Pass (Set-Level)
For each relevant Superset, enumerate the implicated Sets and state:
- Eligibility rationale (why this Set is in play)
- Exclusion rationale (what Sets are explicitly not in play and why)
Rules:
- Still no elements instantiated here.
- No causal claims.

## 7. Element Instantiation (Case-Bound Claims)
Instantiate elements as numbered claims.
Rules:
- Elements must be testable, case-specific, and non-normative.
- Elements must be written as declarative statements.
- Elements may conflict.
- Elements must be scoped to Sets (label each element with Superset → Set).
- Elements are not reusable constructs; do not generalize.

## 8. Evidence Mapping (Optional but Preferred)
For each element, map:
- Supporting evidence
- Contradicting evidence
- Unknowns / missing evidence
Rules:
- Evidence may be documents, observations, or testimony, but must be clearly identified.
- Unknowns must remain unknown; do not speculate.

## 9. Cross-Domain Dependency Notes
Record how elements in different Supersets constrain or interact with each other.
Rules:
- No new elements introduced here.
- This is about dependencies, not conclusions.

## 10. Comparative Explanation Result
State what the REPAC-structured explanation enables that the pre-REPAC hypotheses did not.
Rules:
- No prescriptions.
- No interventions.
- Keep to explanatory auditability and comparability.

## 11. Analyst Notes (Non-Authoritative)
Record any cautions, modelling difficulties, or boundary pressures observed.
Rules:
- This section is explicitly non-authoritative.
- If boundary pressure suggests ontology change, note it without acting on it.
