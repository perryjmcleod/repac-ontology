# REPAC Applications

This directory contains **non-normative applications** of the REPAC v1.0 ontology.

The materials in this directory **do not define, extend, modify, reinterpret, or formalize** REPAC ontology constructs. They demonstrate how REPAC v1.0 may be *applied analytically* to explain organizational outcomes without collapsing explanation into single-factor narratives.

REPAC v1.0 itself is **complete and immutable**. All authoritative ontology artifacts remain outside this directory.

---

## Purpose of This Directory

The purpose of the `/applications` directory is to:

- Demonstrate REPAC v1.0 in use without extending it  
- Provide concrete, comparable analytical examples  
- Illustrate how common organizational misdiagnoses arise  
- Preserve REPAC’s non-prescriptive epistemic stance  

These artifacts exist to support **understanding, teaching, critique, and evaluation** of REPAC as an analytical ontology.

They are not methods, frameworks, workflows, or guidance documents.

---

## Canonical Applications

The `/canonical` subdirectory contains **Canonical Applications (CA)**.

Canonical Applications are:

- Stable, publication-grade analytical walkthroughs  
- Explicitly non-normative and non-prescriptive  
- Governed as explanatory artifacts, not design tools  
- Intended to be cited, taught, and compared  

Each Canonical Application:

- Uses REPAC v1.0 exactly as published  
- Traverses all REPAC domains as necessary but not sufficient  
- Avoids causal collapse into single-domain explanations  
- Makes analytical commitments explicit  

---

## Governance and Stability

Canonical Applications are governed as follows:

- Once published, Canonical Applications are **stable artifacts**
- Silent edits are not permitted
- Corrections require:
  - An explicit errata or clarification note
  - A commit message clearly labeled as `clarification` or `typo`
- No Canonical Application may introduce new ontology constructs
- No Canonical Application may reinterpret existing constructs

If an analysis requires new constructs, it does not belong in this directory.

---

## What This Directory Is Not

This directory does **not** contain:

- Ontology specifications  
- Extensions or variants of REPAC  
- Prescriptive recommendations  
- Best practices or implementation guidance  
- Training curricula or operational playbooks  

Use of REPAC for those purposes, if any, must occur outside the ontology and outside this repository’s authoritative scope.

---

## Relationship to REPAC v1.0

REPAC v1.0 consists of the formally published ontology artifacts, including but not limited to:

- Canonical diagrams  
- Formal ontology representations (e.g., TTL/OWL)  
- Repository documentation explicitly marked as normative  

Materials in `/applications` are **illustrative only** and carry no normative authority over REPAC.
